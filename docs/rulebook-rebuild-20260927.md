### 旧チャンクの問題 (500 文字で機械的に分割していたことによる)

- ほぼ全ページで、`## ページ N` の行だけのチャンクができていた (手作業で無効化した 527 件の大半)
- 有効な 1770 件のうち、1115 件にルビ「漢字（かな）」が計 17,664 個
- 642 件 (36%) が文の途中で終わる
- 目次・奥付・空欄の記入用シート・チェック欄・誌面のレイアウト要素 (サイドバーなど) が混在

## 作り直しの方針

`ai-agents/rulebook_chunker.py` / `build_rulebook.py`。

- `## ページ N` (PDF ページ) と目次から、本のページ (見開き: 2N−4, 2N−3) と「部 > 章 > 項目」を割り当てる。目次との対応は 4 か所で確認済み (例: PDF 125 → 本 246「魔法データ」)
- 見出し・段落単位で分け、文の途中では切らない。表は行単位で分けて見出し行を付け直す
- ルビ、ページ番号、目次の点線、イラストのクレジット、コピーライト行、チェック欄、レイアウト要素を取り除く
- 空欄の記入用シート (本体の行の半分以上が空、または 1 列目のラベルだけ) と、サンプルキャラクターの記入済みシートを捨てる (キャラクター解説の文章は残す)
- 用語集のような「見出し + 1 行」の連続は 1 チャンクにまとめ、見出しを【】で残す
- サンプルシナリオ「蛮族を駆逐せよ」の本文は無効 (`tag='scenario'`) で取り込む。物語の文章がプレイヤーの行動文とよく一致し、GM が今のセッションに持ち込むおそれがあるため
- 埋め込みは「節のパス + 改行 + 本文」

## Orchestrator 側の変更

- 訂正・ハウスルールの `overrides_id` が検索で使われていなかった → 有効な訂正があれば元のチャンクを出さない
- UI から追加・編集したルールに埋め込みが作られず、検索に出てこなかった → 保存時に埋め込む
- GM プロンプトで「【参照ルール】」が二重になっていた → 修正。各ルールに `[節 p.頁]` の出典を付ける
- Support にも、NPC の行動 (魔法名など) で引いたルールを 3 件渡す (消費 MP などの確定用)

移植した DB のコピーで 3 ターン実行し、GM がルールブックの記述 (先制判定の基準値、ゴブリンの先制値) を使って答えることを確認した。1 ターン 14〜16 秒。

## 残っている課題

- **OCR の誤字**: 「穢れ」が「職れ」「縄」になっているなど。原本 Markdown 側の問題で、今回は直していない
- **行動文での検索が弱い**: 「盾で割り込んで後衛を庇う」→《かばう》が出てこない。行動文をそのままクエリにしているため。LLM でクエリを言い換える方法はあるが、呼び出しが 1 回増える
- ~~mlx-serve の bge-m3 プロファイルの入力上限が 512 トークン~~ → mlx-serve の `bge-m3-q8` プロファイルに `--batch-size 2048 --ubatch-size 2048` を追加して解消 (1 入力 2048 トークンまで)。表の分割を 450 → 900 文字に戻して作り直し、チャンクは 1092 件になった。最長のチャンクでも 613 トークン
- `rag_chunks_opt` (LLM による整形) はルールブックには不要になった。テーブルと `optimize_chunks.py` は残してある
