# MLX 基盤に合わせた再チューニングと UI 改修 計画 (2026-11-12)

## 0. 守るもの (元々のコンセプト)

ソード・ワールド 2.5 の **完全自律型 AI-TRPG**。ローカル LLM だけで、プレイヤー 1 人が行動を宣言すると、
**GM・最大 3 体の NPC (それぞれペルソナを持つ)・数値確認役** が自動でセッションを進める。
ルールブック RAG、3 レーンの戦闘配置、チェックポイント、クエストボード、PC シート、シーン画像。

この計画で変えるのは「どう動かすか」と「どう見せるか」。上の体験そのものは変えない。
ターンの流れ (GM → NPC×3 → 数値確認、1 モデル直列、NG なら段ごとに再思考) も維持する。

## 1. 現状の問題 (2026-11-12 調査)

### 基盤とのずれ
| 問題 | 影響 |
|---|---|
| mlx-serve の Gemma プロファイルに `APC_CHECKPOINT_GUARD_TOKENS=8` / `APC_CHECKPOINT_ENTRIES=4` が無い | 1 ターン約 42 秒のはずが約 55 秒 (verification-apc-20261005) |
| APC のテナントを指定していない | 汎用チャットなど他アプリとキャッシュを奪い合う |
| UI のタイムアウト 180 秒 / サーバは 1 呼び出し 300 秒 × 最大 15 回 | 画面はタイムアウト表示、サーバは後から完了して配信 |
| UI に旧構成 (llama-server 6 プロセス、:11430-11435、E4B/E2B) の表示が残る | 誤情報 |
| LLM の稼働状態を返す API がない | 画面で「モデルが起動していない」が分からない |

### コンセプトを損なっている点
| 問題 | 該当 |
|---|---|
| **ターンをまたいだ記憶がない** (毎ターン新しい会話) | GM が前のターンを知らない |
| **NPC にペルソナを渡していない** (名前・HP・MP・レーンのみ) | 口調・行動が似る |
| PC・受注中クエスト・シナリオが LLM に届いていない | 冒険の目的が GM に無い |
| **チェックポイント復元が NPC の HP/MP/位置を戻さない** | 「任意時点への復元」が成立していない |
| ターン番号を画面のローカル状態で数えている (再読込で 1 に戻る) | 実 DB にターン 1 のチェックポイントが 6 件重複 |
| GM 直訴が NPC・数値確認まで回すフルターンになっている | 質問のたびに NPC が行動し HP/MP が動く |
| ルールの優先度 (ハウスルール > 訂正 > ルールブック) が同点時の並び替えにしか効かない | ハウスルールが負ける |
| 1 セッションに同時に 2 ターン走れる (排他なし) | 状態の競合 |
| ComfyUI 連携が動かないスタブ (KSampler 単体のグラフ) | 画像機能が実質無い |

### UI
- SESSION_ID=1 固定。セッションの作成・選択ができない
- プレイヤー自身の入力が表示されない (「(アクション送信)」固定)
- 約 40〜55 秒のターン中、どの段にいるか分からない (経過秒だけ)
- `warnings` / `stage_attempts` (再思考・欠落) を表示していない。参照したルールも見えない
- PC カード・敵・状態バッジ・HP バーの幅が固定値
- PARTY 画面の保存でペルソナ (personality / backstory / action_rules) が消える。ポートレート生成はモック
- RULES 画面に検索が無く、1093 件を一括取得
- `@media` が無くスマホで使えない。エラーは握りつぶしか生テキスト
- 未使用コンポーネント (BattleMap 10×10 など) と lint エラー 6 件

## 2. MLX 側で得た利点・反省から採るもの

| MLX での知見 | Omni-Master での使い方 |
|---|---|
| 毎ターンの指示は system ではなく **最後の user メッセージの末尾** に置くと守られる (5637e15) | 状態・ルール抜粋・段の指示は末尾。履歴には残さない |
| **履歴は記憶ではない**。固定の前置き + 記憶の呼び出し + 直近の数往復。前置きは APC が効く (TTFT 5.8 s → 0.25 s) | セッション固定の前置き (卓の約束・世界・PC・NPC ペルソナ・クエスト) + 要約 + 直近 N ターン |
| 要約は未要約の部分だけ、主語を明示した 1 文ずつ (kappa の summarize) | 数ターンごとにセッション要約を更新し、前置きの直後に置く |
| **ダイスと状態はコードが持つ** (LLM に 2d6 を振らせる GM ロールは即日廃止) | 判定はコードが 2d6 を振り、LLM には結果を渡して描写させる |
| 出力検証は小型 LLM ではなく **ルールで** (agent-guard、LFM3 の秘書役は不採用) | 既存の段ごとの検証 + 再思考を継続・強化 |
| 構造化データは **キーで引く**、ベクトル検索は自由文だけ (Kappa) | 特技・魔法・アイテム・魔物名は用語インデックスで確定的に引き、残りを埋め込み検索 |
| 類似度のしきい値 (0.45) を実測で決める、使った記憶を UI に出す (🧠) | RAG にしきい値、各ターンで参照したルールをチップ表示 |
| **NDJSON ストリーミング**、⏹ で途中保存、job id で長時間処理を再送しない | 段ごとの進行と GM/NPC の本文を逐次配信 |
| 名前「台詞」形式はコードで扱える | NPC の台詞表示・将来の読み上げに使う |
| 画像のタイミングはコードが決め、構図はディレクター役が 1 回で決める | 画像は MLX の画像工房 (studio) API を使う |
| 共有テーマ (theme.css / ui.css)、375px で崩れない、確認ダイアログは共通部品、エラーは次に何をすべきかを書く | UI の見た目と振る舞いを MLX の画面に揃える |
| 再生成 ↻ / 編集して再送 ✎ / ここから削除 🗑、続きから / 新しく | ターン単位の作り直し・巻き戻し、セッションの再開 |
| Gemma MTP は `response_format` 不可 (500)、temperature/seed が効かない可能性 | JSON はプロンプト指示 + 寛容なパース (現状維持)。多様性はペルソナと前の NPC の行動で出す |

## 3. フェーズ

### Phase 1 — 基盤との接続を合わせる (小)
1. LLM / 埋め込み / ComfyUI の稼働状態を返す `GET /api/system` (mlx-serve ダッシュボードの `/api/status` も参照)
2. `X-APC-Tenant: sw25` を送る
3. タイムアウトを 1 本化 (サーバ側のターン全体の上限を設け、UI は進行イベントで待つ)
4. mlx-serve 側の APC 設定 (`APC_CHECKPOINT_GUARD_TOKENS=8`、`APC_CHECKPOINT_ENTRIES=4`) を **ユーザーに依頼** (MLX リポジトリは触らない)

### Phase 2 — セッションの正しさ (中)
1. セッションの作成・一覧・選択 (SESSION_ID 固定をやめる)
2. ターン番号はサーバが決める。セッション単位の排他 (同時ターン禁止)
3. チェックポイント復元で NPC の HP/MP/位置も戻す。ターン削除で turn_results も消す
4. GM 直訴は GM 段だけを回す (NPC・数値確認は動かさない)
5. ルールの優先度を順位に反映 (ハウスルール・訂正を上に)

### Phase 3 — 記憶とペルソナ (中、コンセプトの中核)
1. セッション固定の前置き: 卓の約束 + 世界 + PC シートの要点 + NPC ペルソナ (personality / backstory / action_rules) + 受注クエスト。APC が効くよう、変わらない順に並べる
2. 直近 N ターン (既定 2) を前置きの後ろに置く
3. セッション要約: 数ターンごとに、未要約の部分から主語付きの 1 文を 3〜6 個作り、前置きの直後に置く
4. 毎ターン変わるもの (HP/MP・レーン・参照ルール・段の指示) は最後の user メッセージの末尾
5. 検証で比較: 記憶の有無で、前のターンの出来事・NPC の口調の一貫性・1 ターンの所要時間

### Phase 4 — 進行のストリーミングと UI 改修 (大)
1. 段ごとの進行イベント (GM 生成中 → NPC A → … → 数値確認、再思考中) と GM/NPC 本文の逐次配信 (WebSocket)
2. ⏹ 中断 (途中まで保存)、↻ 直前のターンを作り直す (チェックポイントから)
3. MLX 共通テーマ (theme.css / ui.css の変数・クラス名に揃える、ダークモード、375px)
4. 画面構成 (現行 5 画面の役割は維持):
   - **開始**: 続きから (最近のセッション) / 新しく (クエスト・PC・NPC を選んで開始)
   - **SESSION**: 会話ログ (プレイヤー・GM・NPC の吹き出し、NPC は名前「台詞」)、進行表示、参照ルール・再思考・欠落のチップ、戦闘配置 (3 レーン)、パーティの HP/MP (実値)。スマホではログ優先で、配置とパーティは引き出し
   - **QUEST**: 受注・完了をここで
   - **PARTY**: ペルソナを消さない保存 (YAML のキーを保ったまま値だけ更新)
   - **RULES**: 検索 (RAG と同じ検索 + 用語の完全一致)、ページング
5. 共通の確認ダイアログ、エラーは次の行動を書く、旧ポート表示と未使用コンポーネントの削除、lint 0

### Phase 5 — ルール参照と判定 (中)
1. 用語インデックス: 《》【】〈〉の特技・魔法・アイテム・魔物名を読みで照合し、該当チャンクを必ず含める (庇う/かばう 対策)
2. 類似度のしきい値を実測で決める
3. 判定をコードで: NPC/GM が「判定: 種類・基準値・目標値」を出したらコードが 2d6 を振り、結果を数値確認と描写に渡す (自動成功 12・自動失敗 2)

### Phase 6 — 画像 (任意)
1. 動かない ComfyUI スタブを捨て、MLX 画像工房の `POST /api/studio/infer` → `/render` を使う
2. 画像は数ターンに 1 回、コードが決める。生成画像は保存して turn_results に紐付ける

## 4. 進め方
- 各フェーズで Go テスト・pytest・lint を通し、実機 (mlx-serve) で通し実行して記録する
- MLX リポジトリは変更しない。必要な設定はユーザーに依頼する
- Phase 1→2→3 は直列。Phase 4 の UI は Phase 2 の API 変更の後
